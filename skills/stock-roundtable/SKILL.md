# 游资风格圆桌会议

## 定位

把同目录下的9个风格 Skill 变成一场有固定规则的会议：每位辩手只用自己 Skill 里的框架选票，选不选、选哪只都只看自己的框架；不给别人的票投票，也不质询别人。主持人不评判，只统计每只股票被几位辩手选中：2 位及以上选中的是**共识票**，按票数从多到少排（3 位选中的排在 2 位选中的前面；票数相同，先比把它当第一选择的人数，再比成交额）。共识票不设上限；没有共识票就空仓，不凑数。

目标不是“找到必涨股”，而是看不同框架在哪些股票上不约而同。

四种用法：

0. **对话窗口**：双击 `启动对话窗口.bat`，在聊天窗口里用指令开会、点名提问、让 9 位辩手讨论某只股票（见“对话窗口”）。
1. **指定交易日开会**：`run_day.py <日期> --time HH:MM`，用 `D:\data` 里那一天截至该时点的分钟线开一次会，记录每位辩手的判断、选票和理由、唱票和共识票（见“指定交易日开会”）。
2. **实时圆桌**：用户提供某个时点的盘面数据，由你担任主持人，请 9 位辩手按各自的 Skill 选票，再唱票（流程见下文）。
3. **回测引擎**：`run_backtest.py` 在 `D:\data` 的每个有效交易日上自动开会（盘中 10:00 和收盘后 15:10 复盘两场），输出每场的记录和统计（见“回测引擎”）。

## 边界

- 辩手是“按某个 Skill 规则化的风格模型”，不是本人。不得以第一人称冒充，不得编造语录；引用原话只能用各 Skill 里标了证据等级的句子。
- 每位辩手只能用决策时点之前已经发生的数据。龙虎榜收盘后才披露，盘中不可用；用户没给的数据（新闻、公告、题材归属）要写“缺失”，不能补编。
- 普通A股 T+1；涨停时只能排队，不能假设成交；跌停时可能卖不出。
- 输出是研究记录，不是买卖指令。不得写“必涨”“稳赚”。

- 左栏可以直接选交易日和时点开会；点辩手名字就是“某某怎么看”。
- 每场会的完整记录同时写到 `output/days/<日期>_<时点>.md`。
- 窗口里的每一句辩手发言都是规则引擎生成的，和回测用同一套规则；不是 AI 即兴发挥，也不会看到开会时点之后的数据。问不在引擎范围内的问题，窗口会提示可用指令。

## 指定交易日开会

> **Python 环境**：本机 PATH 里的 `python` 会解析到没有 numpy/pandas 的托管 3.13.12，直接跑会 `ModuleNotFoundError: numpy`。下面所有命令里的 `python` 都指 `C:/Users/hdy11/AppData/Local/Programs/Python/Python310/python.exe`（numpy 1.26.4 / pandas 2.2.0）。

```
python -X utf8 run_day.py 2026-09-24                        # 当天盘中 10:00 和收盘后 15:10 复盘两场
python -X utf8 run_day.py 2026-09-24 --time 10:30           # 只开 10:30 一场（盘中任意 09:31–11:30、13:01–14:59 的分钟；15:00 以后都按收盘后 15:10 复盘）
python -X utf8 run_day.py 2026-09-24 --time 14:00 --blind   # 不写事后结果，只看决策
python -X utf8 run_day.py 2026-09-24 --time 10:30 --audit   # 顺带做一次防偷看审计
python -X utf8 pick_qc.py 2026-09-30 603127 603538          # 选票位置体检（进名单前的硬闸门）
python -X utf8 pick_qc.py 2026-09-30 --all-top 60           # 全市场体检：当日成交额前 60 只
python -X utf8 pick_qc.py 2026-09-30 --candidates           # 体检最近一份报告里出现过的代码
```

- 记录写到 `output/days/<日期>_<时点>.md`，终端同时打印共识票（票数和选它的辩手；也可能一只都没有）和每位辩手的选票。
- 记录的结构：主持人盘面简报 → 各位辩手的选票（判断、买入意愿、选票①②及理由，或不选的原因）→ 主持人统计（唱票）→ 共识票（按票数排，或空仓）、仓位意见和共识票的理由 → 事后结果（决策时不可见：买入时涨幅、买入日收盘涨幅和收益、次日最高/最低/均价涨幅、T+1 三种卖出收益）。
- 09:31–14:59 是盘中会议（按该分钟价格买入；共识票里已封涨停的只能按涨停价排队，之后开板才算成交）；15:00 以后是收盘后复盘，统一记作 15:10（看全天分时，次日开盘买入）。成交额类门槛在 10:00 和收盘两个锚点之间按已过的分钟数插值，10:00 和 15:10 与回测完全一致。
- **收盘后复盘定在 15:10**：数据里最后一根分钟线是 15:00，已经包含 14:57–15:00 的收盘集合竞价，收盘价在 15:00 就定了；定在 15:10 是为了确保收盘数据已经到齐再开会。所以当天北京时间 15:10 之前不开收盘后复盘；文件里不到 99% 的股票有 15:00 那根分钟线（还没收完）也不开。历史交易日上，15:10 复盘看到的数据和原来的 15:00 场完全一样，选票不变。
- 情绪阶段要和此前每个全市场交易日的同一时点比较，所以某个时点第一次开会要逐日算一遍历史（几分钟），之后缓存在 `cache/market_<时点>.json`；跑过全量回测后，10:00 和 15:10 不用再算。
- 回测已经为 `D:\data` 里的全部有效交易日写好了 10:00 和收盘后 15:10 的记录：`output/intraday/<日期>.md`、`output/eod/<日期>.md`，可以直接打开。

**新的交易日**：把当天的1分钟 CSV（与现有文件同格式，文件名 `<日期>.csv`）放进 `D:\data`，先运行 `python -X utf8 fetch_xdxr.py --refresh` 更新除权除息，再运行 `run_day.py`。日线历史之后的交易日由分钟线自动生成日线。盘中还没收完的文件只能开截至文件最后一分钟的盘中会，事后结果等收盘后的完整文件；收盘后复盘要等 15:10 以后、换成收盘后的完整文件再开。

**在对话里使用**：说“用 stock-roundtable 开 2026-09-24 10:30 的圆桌”，你先运行 `run_day.py`，再按记录逐项讲解；如果用户另外提供了新闻、公告或题材信息，可以在讲解时补充，但必须标明“规则引擎没有使用这部分信息”，不能改写引擎的选票和共识结果。

## 实时圆桌流程

### 第0步：时间戳与数据清单

写明决策时点（例如“2026-06-02 10:00”）和手上有哪些数据、截至什么时候。至少需要：全市场涨跌家数、涨停/炸板/跌停、昨日涨停今日表现、连板梯队、行业或题材的涨停分布、候选股的分时（均价线）与成交额、5/10/20日均线。缺什么写什么。

### 主持人盘面简报

市场宽度、量能、涨停结构、最高板、主线方向、情绪阶段（炒股养家框架）、周期（92科比框架）。只陈述事实和各框架的分段结果，不表态。

### 第 0.5 步：选票体检（**可选**，默认关闭）

> **2026-10-07 用 40 个交易日（94 只票）实测过：闸门对收益是中性。**
> 放行 56 只 ／ 挡掉 38 只：平均收益 **+0.46% vs +0.46%**（持平），胜率 48% vs 50%（持平）；
> 差别只在尾部 —— 挡掉的那组最好 +5.06%（放行 +4.61%）、最坏 -4.13%（放行 -3.69%）。
> **它是削峰填谷的风险控制工具，不是收益工具。** 别指望它提高胜率。
>
> **默认按原圆桌逻辑开会**（不加闸门）。想用它的时候：
> `review_picks.py --days N` 事后复核，或 `backtest_funnel.py` 开启 `config.POSITION_GATE` 重跑。

做这个闸门的起因是：同一决策时点开了三场会，一号驿分别是襄阳轴承 → 昭衍新药 → 恒瑞医药。
它治的是"位置陷阱"类纪律错误（百普赛斯 60 日 +189% 被当低吸、襄阳轴承位置 100% 拿 4 票），
**不是为了提高收益** —— 这一点实测已经说清楚了。

```
python -X utf8 pick_qc.py 2026-09-30 603127 603538 600276    # 指定票
python -X utf8 pick_qc.py 2026-09-30 --all-top 60            # 全市场：当日成交额前 60 只
python -X utf8 pick_qc.py 2026-09-30 --candidates            # 体检最近一份报告里出现过的代码
```

**F3 必须跑全，不许抽样**：2026-10-07 首跑时只体检了 56 只涨停里的 27 只，却在报告里写"压到 8 只"（真实是 36 只放行）。报告里"X 只里合格 Y 只"的 Y 只有在**分母跑全**时才成立。

冻结口径（改常量就要在文件头写理由）：

| 闸门 | 口径 | 挡住过的实例 |
|---|---|---|
| 突破 | 创 **60 日**新高且收盘在前高之上 | 恒瑞医药 9-30 的 47.39 在 12 根 K 里是新高，60 日里不是 |
| 低吸 | 60 日涨幅 ≤ **50%** 且 60 日区间位置 ≤ **80%** | 百普赛斯 60 日 +189% |
| 回流 | 当日上影 ≤ **3%** | 义翘神州 3.64%、近岸蛋白 4.55% |
| 可买 | 当日振幅 ≥ **0.2%**（识别一字） | 园林股份封成比 3536 |

输出还带**形态分类**（急涨到顶 / 慢牛爬升 / 中段 / 偏下 / 底部区，60 日跌幅 >20% 额外标"（阴跌）"）。FAIL 的票要进名单，必须在报告里写明为什么仍然要它。

**闸门的两条已知边界（别当万能钥匙用）**：

1. **涨停票的位置百分位恒等于 100%**（区间上沿含当日最高价），所以「涨停且创新高」的票原本会被机械判死。脚本已放宽：收盘价≈最高价且收在箱体上沿时，位置门槛放宽到 100，改由 60 日涨幅单独把关，判定显示 `PASS(涨停放宽位置,涨幅把关)`。代价是**对涨停票只剩涨幅一条在把关**。
2. **低吸只有上限没有下限**：60 日跌 40% 的票和横盘的票一样 PASS（中际旭创 -27.94%、兆易创新 -42.92%）。形态会标"（阴跌）"，但闸门不判断是低位还是下跌中继 —— 这条要人工看。
3. **它是排雷工具，不是精选工具**。9-30 实测：56 只涨停票里放行 36、剔除 20，剔除的全是 60 日涨幅 >50% 的。别指望它把 56 只筛成 5 只。

### 第一项：各自选票

按上表顺序，每位辩手：

1. 用自己的框架给出今天的市场判断和**买入意愿**（0–100%，空仓=0）；
2. 只按自己的框架选 0–2 只股票，第一只是第一选择；每只写明用的是本 Skill 里的哪个模式，以及支撑它的具体数据（价格、分时位置、成交、板块）；
3. 没有符合条件的股票就写“不选”和原因。

辩手之间不互相投票、不质询、不答辩；别人选了什么不影响自己的选择。

### 第二项：主持人唱票

- 统计每只股票被几位辩手选中、谁选的、谁把它当第一选择；
- 被 2 位及以上选中的是共识票，按票数从多到少排（3 票在 2 票前面）；票数相同，先比当第一选择的人数，再比成交额；
- 共识票不设上限，也不补位；没有共识票就宣布本场空仓；
- 盘中会议里，已封涨停的共识票照样排名，但注明只能按涨停价排队，开板才算成交；
- 写出圆桌仓位意见：参与辩手的平均买入意愿、不选的人数；
- 列出每只共识票的选票理由（各位辩手各自的模式和数据）。主持人不加入自己的判断。

## 回测引擎

```
python -X utf8 run_backtest.py                        # D:\data 全部有效交易日，盘中 10:00 与收盘后 15:10 复盘两种模式
python -X utf8 run_backtest.py --start 2026-06-01 --end 2026-06-05 --out output-test
python -X utf8 show_transcript.py output\intraday\2026-06-02.md 主持人统计 共识票 事后
python -X utf8 study_t1.py                            # 每位辩手单独操作、T+1 卖出（写 output/study-t1/）
python -X utf8 study_consensus.py                     # 共识票的逐日明细（写 output/study-consensus/；先跑 study_t1.py）
python -X utf8 study_confirm.py                       # 15:10 复盘观察池次日盘中每分钟确认（≥2 位辩手按原规则投“买”才买）vs 开盘直接买（写 output/study-confirm/；--step 5 改成每 5 分钟）
python -X utf8 study_own_confirm.py                   # 各自确认：每位辩手次日按自己的盘中规则决定是否真买自己的 15:10 复盘选票（写 output/study-own-confirm/）
```

- **有效交易日**：`D:\data` 中覆盖全市场（≥5400只）的交易日；更早的不完整日只作为历史；每个文件都要收完（至少 99% 的股票有 15:00 收盘那根分钟线，当天还要过了 15:10），遇到没收完的文件回测直接停下，不会把收盘前的选票写进 `pending.csv`。
- **两种会议**：盘中 10:00（只看 09:31–10:00 的分钟线，当日 10:00 价格买入）；收盘后 15:10 复盘（看全天分时，含 15:00 收盘集合竞价那根，次日开盘买入）。
- **防偷看**：历史只读前一交易日及以前的日线；当日只读开盘前已知的昨收与涨跌停价，以及截止时点之前的分钟线；收益在决策记录之后才计算；每隔10个决策日把截止时点之后的全部数据换成随机数重跑一遍，选票和共识结果必须完全一致（结果写在 `audit.json`）。
- **买入**：10:00 场按当天 10:00 价格；15:10 复盘按次一交易日开盘价；买入时已在涨停价的只能按涨停价排队，之后开板才算成交；次一交易日停牌（没有成交）的不成交。
- **卖出（A股 T+1）**：买入后的下一个交易日，按当天最高价（最佳，事后才知道，做不到）、高低均价（平均）、最低价（最差）三种算；另列买入时涨幅、买入日收盘涨幅和收益、次日最高/最低/均价涨幅。已扣除除权除息影响，未扣交易费用（来回约 0.1%）。卖出日一字跌停实际卖不掉，按跌停价计入并在记录里标出（`t1_stuck`）。
- **组合口径**：每场一份资金，平分给这场的共识票（没成交的那份留作现金）；没有共识票的会议算现金（收益为 0）；只统计 T+1 卖出日已有数据的会议。`summary.md` 同时列出每场共识票数的分布。
- **对照组**：同日全部可选股、选票池（任何辩手选中的票）、未封板涨幅最大的3只。
- **输出**：`output/<模式>/<日期>.md`（每场的完整记录）、`picks.csv`（共识票：票数、选它的辩手、买入和 T+1 卖出结果）、`nominations.csv`（每位辩手的每张选票及结果）、`days.csv`、`pending.csv`（最后一场 15:10 复盘的共识票，等下一交易日开盘买入）、`summary.md`、`audit.json`。

规则化的限制（解读结果前必读）：

- 每位辩手只是本 Skill 的一个可执行近似，阈值在看结果之前一次写定，没有按回测调参；
- 没有新闻、公告、概念板块和龙虎榜数据：题材用通达信行业和分时联动簇近似，瑞鹤仙的逻辑链只能做资金验证；
- 名称、ST 标记和行业来自 2026-08-22 抓取的快照（不含价格信息），只影响涨跌幅档位和行业归类；
- 数据只含下载时仍在上市的股票（幸存者偏差）：期间退市的股票不在数据里，5–8 月的统计可能偏好看；
- 大盘用全A等权代理指数，不是上证指数；
- 样本只有约4个半月，属于样本内观察，不能外推。

### 全市场漏斗（别从涨停榜开始）

只在涨停榜里挑票，结论会被初始候选池框死 —— 没涨停的票（哪怕成交 38 亿、创 60 日新高）永远不会进入视野。开会按这个顺序走，**每一步的产物要能贴出来**：

| 步 | 动作 |
|---|---|
| F0 | 固定取数清单：涨停全名单 / 主力净额前 20 / 涨幅 5% 未涨停前 20 / **创 60 日新高且成交 >15 亿** / 振幅 >12% 且收涨 |
| F1 | 按"涨停原因"做题材聚类（**不是行业分类**） |
| F2 | 主线判定：容量 + 梯队 + 资金，缺一不算 |
| F3 | 位置体检 `pick_qc.py`（**可选**；若开闸门则必须在 F5 投票之前） |
| F4 | 可买性过滤：**封成比 >50 剔除、一字剔除**（阈值 50 为冻结值，封成比来自通达信 screener 涨停结果，本地日线没有这个字段） |
| F5 | 票数统计 |
| F6 | 写报告，必须含：取数清单、闸门表、每只票的证伪条件、跨版本稳定结论、已知盲区 |

已知口径陷阱：**"涨停原因/原因揭秘"是当日截面，看不到时间轴**。用它判断"新方向/新周期"会错（9-30 的创新药其实是 9/21–9/24 第一波之后的第二波，不是新方向）。判断"新不新"必须用日 K。
